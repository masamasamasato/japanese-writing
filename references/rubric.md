# 文章の採点表

`scripts/check.py` では測れない項目を、Claude が読んで採点する。各項目を 0〜2 点で評価し、合計 20 点満点で示す。

スクリプトの点数と採点表の点数が食い違ったら、採点表を信じる。スクリプトは文の形しか見ていない。読みにくい文章の多くは文は整っていて、構成に問題がある。

| 点 | 意味 |
|---|---|
| 2 | 問題なし |
| 1 | 一部に問題がある。具体的な箇所を挙げる |
| 0 | 全体的に問題がある |

## 採点項目

### 読みやすさ（8点）

1. **結論が先にある** — 冒頭3行で何の話か、結論は何かがわかる
2. **目次・見出しだけで筋が伝わる** — 見出しが分類ラベルではなく主張になっている（短い文章で見出しがない場合は、段落の先頭文で判定する）
3. **一段落一トピック** — 段落の途中で話題が変わっていない
4. **順序が自然** — 前提が後から出てこない。読み手が戻って読み直す必要がない。原因や理由を書く文章では、本命が一つに絞られ、他の候補は最後にまとまっている。根拠のある事実は言い切られ、推測は推測と分かる形で分かれている

### 簡潔さ（4点）

5. **情報のない文がない** — 前置き、結び、言い換えの繰り返しがない。同じ確定情報（決定・スケジュール・数値）を二か所に書いていない
6. **足場がある** — 冒頭に出る重要語が、知らない人にもわかる形で説明されている。用語より先に具体例や数字がある。用語が用語で定義されていない。「パフォーマンス向上」ではなく数値や事象で書かれている

### トーン（4点）

7. **文体が統一** — 敬体・常体、表記揺れ、敬語の程度が一定
8. **読み手が一種類** — 一般解説と個別の話、初心者向けと実装者向けが混ざっていない。混ざるなら線で分かれている

### 自然さ（4点）

9. **音読してつかえない** — 助詞の連続、語尾の単調さ、修飾の絡まりがない。「ざっくり」「だいたい」「≒」「おそらく」「ようです」が重なっていない
10. **人が書いた文章に読める** — AI調・翻訳調の型（「重要なのは」「〜しましょう」「あなた」）がない

## 出力形式

評価を頼まれたら次の形で返す。

```
機械チェック: 82 / 100（80字超 2文、冗長表現 3件、文体 敬体）
採点表: 14 / 20

- 結論が先にある: 1 — 結論が2段落目にある。冒頭に移す
- 見出しで筋が伝わる: 0 — 「背景」「実装」「まとめ」がラベルのみ
- 足場がある: 1 — 「高速化した」に数値がない
（2点の項目は省略）

一つだけ直すなら: 見出しを主張に書き換え、結論を冒頭に移す
```

2点の項目は列挙しない。問題のある項目だけを、箇所と直し方つきで挙げる。最後に「一つだけ直すならこれ」を示す。点数を出すこと自体が目的ではなく、次に何を直すかがわかることが目的。

全体が良い文章なら、そう言う。合計が 17 点以上で、直すべき点が一つしかないなら「良い部類です。直すなら〇〇だけ」で済ませ、指摘をひねり出さない。
